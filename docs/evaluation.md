# Evaluation

How extraction quality is measured, what the numbers are, and why the runtime extractor is rules-only. Every figure below is from a committed file (linked) and can be reproduced; the dataset is named next to each number. 

## Dataset

80 synthetic service-agreement PDFs, generated byte-identically on every run (`python3 corpus/generate.py check` compares each to the SHA-256 in [`corpus/manifest.json`](../corpus/manifest.json)). Every organisation, person and amount is invented. Ground truth for each case is in [`corpus/expected/extract/`](../corpus/expected/extract/): the expected status of each of the 7 fields, its value, and the expected evidence text.

| Split | Cases | Role |
|---|---|---|
| `dev` | 22 | The rules were written against these. Every accuracy gate is hard (100 %). |
| `heldout` | 8 | Written from the contract before any extractor existed; gated on no regression. |
| `heldout-2` | 16 | Pre-registered before any prompt or model existed; measures assisted-1. |
| `heldout-3` | 24 | Pre-registered before assisted-2 was frozen; measures assisted-2. |
| `assist-dev` | 10 | Disjoint templates used to develop assisted-2. |

Expected evidence is registered as `{page, text, occurrence}`, so a returned span counts if it contains that occurrence; expectations do not depend on how an extractor chooses its quote.

| `heldout` | 8 | 0.6964 | 0.5143 | 0.625 | 0 | 0 |

Sources: [`heldout-baseline.json`](../corpus/eval/heldout-baseline.json), [`heldout-2-baseline.json`](../corpus/eval/heldout-2-baseline.json), [`heldout-3-baseline.json`](../corpus/eval/heldout-3-baseline.json); dev is a hard gate in `make eval`. Abstention recall is 1.0 on every held-out split: when the rules do not find a value they say so. The held-out misses are unseen phrasings that fail conservatively to UNKNOWN or needs-review, not invented values. The same author wrote the held-out documents and the extractor (see Limitations), so dev being 1.00 shows the rules fit their own cases, not that they generalise; the held-out rows are the generalisation signal.

## Model-assisted extraction: measured, not enabled

Design ([`assisted.py`](../apps/api/src/api/extraction/assisted.py)): the rules run first and their results are final. For fields the rules left `not_found`, a model proposes quoted mentions; it decides no value. Each mention is verified deterministically (the quote must occur verbatim on that page, offsets computed locally) and then passes through the same normalisers and contract checks as the rules' own mentions. A wrong or missing model answer leaves the rules' result unchanged.

Protocol: the held-out split and the decision thresholds were committed before the model-assisted extractor existed ([`heldout-2-preregistration.md`](../corpus/eval/heldout-2-preregistration.md), [`heldout-3-preregistration.md`](../corpus/eval/heldout-3-preregistration.md)). Each configuration (prompt hash, model, effort, verifier version, output schema hash) was frozen and pushed before its first held-out call, then measured in three runs. Rule: enable only if every hard gate holds on every run, every primary threshold holds on the worst run, and the budget holds. Otherwise report it as measured and ship rules-only.

Worst of three runs against `rules-1` on the same split (model `claude-sonnet-5-5`, synthetic data only):

| | assisted-1 on `heldout-2` (16 cases) | | assisted-2 on `heldout-3` (24 cases) | |
|---|---|---|---|---|
| | rules-1 | assisted-1 | rules-1 | assisted-2 |
| Field accuracy | 0.6339 | **0.9643** | 0.7679 | **0.9762** |
| Evidence completeness | 0.3538 | **0.9385** | 0.4459 | **0.9459** |
| Abstention recall | 1.0 | 1.0 | 1.0 | 1.0 |
| Conflict recall | 0.5 | 0.5 | 0.0 | 0.0 |
| Wrong values | 0 | **2** | 0 | 0 |
| Silent conflicts | 1 | 1 | 2 | **3** |
| p95 latency per call | | 3.58 s | | 2.80 s |
| Mean cost per call | | USD 0.0058 | | USD 0.0058 |

- **assisted-1 failed "wrong values not above rules".** On `h2-p3` the model quoted defined short names verbatim instead of the full legal names, so a plausible but wrong party name was accepted.
- **assisted-2 fixed that** with reject-only party-name checks (0 wrong values and 0 wrong party names), but its worst run had 3 silent conflicts against 2 for rules, so it failed "silent conflicts not higher".
- The pre-registered decision for both is `enable_assistance = false`. The stop rule allowed no third attempt, and nothing was tuned on held-out data. The runtime therefore uses the rules only. The assisted code is imported only by the evaluation tooling ([`scripts/eval_assisted.py`](../apps/api/scripts/eval_assisted.py)), not by the API or the worker.
- Assistance raised accuracy and evidence completeness substantially, and still failed gates that were fixed in advance. Reports: [`assisted-1-report.json`](../corpus/eval/assisted-1-report.json), [`assisted-2-report.json`](../corpus/eval/assisted-2-report.json).

## Reproduce

```sh
make eval              # needs Docker and the parser image: dev gates (hard), held-out vs baselines
make eval-assisted     # replays the committed model responses (no model call) and must reproduce the reports
```

`make eval-assisted` needs no API key (it still runs the parser through the image) and makes no model call: every model response is committed under `corpus/eval/assisted-*/run-*/`, keyed by the hash of the exact request, and CI re-scores them on each run. Only a new measurement would call the provider, and it refuses held-out calls without a matching frozen configuration.

## Limitations

- **Same author.** One author wrote the held-out templates and the extractors. Pre-registration, freeze order, generated ground truth and disjoint templates mitigate this; they do not remove it. Held-out measures unseen phrasings, not independence.
- **Small and regular.** 16 and 24 cases (112 and 168 fields). Generated text is more regular than real agreements. Treat the numbers as directional evidence reported with their counts.
- **One document type.** Service agreements, 7 fields, text PDFs only (no OCR).
- **No retrieval or ranking metrics**: nothing here retrieves.
- **Not a judgment on models in general.** It measures one model, one prompt family and one verifier on this corpus.
- Held-out splits are spent: further tuning on them would invalidate them, so any new phrasing becomes a new dev case and needs a fresh held-out set.
