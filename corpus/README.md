# DI-1 synthetic corpus

Fictional, benign service agreements and structural edge cases for the DI-1 parser and extraction evaluation. Every organisation, person and amount is invented.

- **`pdfgen.py`, `cases.py`:** a standard-library PDF writer and the cases (46 written by hand, plus the 34 produced by `generated.py`: heldout-3 and assist-dev; 80 in `manifest.json`). The PDFs are generated byte-identically on every run and are not committed; `manifest.json` pins each case's SHA-256. Check with `python3 corpus/generate.py check`.
- **`expected/parse/<case>.json`:** the parser's expected output (DI-1 PR 1).
- **`expected/extract/<case>.json`:** the expected `service_agreement.v1` result. It is either an `outcome` (`completed` / `needs_review`) with every field's `status`, `reason` and candidate values, or `failed` with the parser's `failure_code`. Evidence is registered as `{page, text, occurrence}`: the value as written, and which occurrence on that page. A returned evidence span must contain that occurrence, so expectations don't depend on how an extractor chooses its quotes.
- **`eval/heldout-baseline.json`, `eval/heldout-2-baseline.json`:** the committed metrics of the rules extractor on each held-out split, which `make eval` must not fall below.
- **`eval/heldout-2-preregistration.md` and `.json`:** heldout-2's coverage categories, the SHA-256 of every expected output, the measurement protocol and the success thresholds for AI1, frozen before any model-assisted extractor exists (a test fails if the expected outputs or the case list change).
- **`eval/assisted-1-config.json`:** the frozen model-assisted configuration (AI1): extractor version, prompt SHA-256, model, effort, output limit, inference location, sampling, output-schema SHA-256 and SDK. Committed before the first held-out call; `make eval-assisted` refuses held-out calls without it and stops if the code no longer matches it.
- **`eval/assisted-1/run-<n>/<request sha256>.json`, `eval/assisted-1-report.json`:** the three frozen measurement runs of assisted-1 (every model response, by the exact request's hash; no request or key) and their report. `make eval-assisted` replays them offline. Results and the decision: [`docs/evaluation.md`](../docs/evaluation.md).
- **`eval/assisted-2-config.json`, `eval/assisted-2/run-<n>/<request sha256>.json`, `eval/assisted-2-report.json`:** assisted-2 (reject-only party-name checks; frozen before its held-out calls), its three measurement runs on dev, heldout and heldout-3 (heldout-2 never sent) and their report, replayed offline by `make eval-assisted`. Results and the decision: [`docs/evaluation.md`](../docs/evaluation.md).

## Splits and integrity

| Split | Cases | Use |
|---|---|---|
| `dev` | 22 (6 of them parser failures) | Rules are written against these. Every accuracy gate is hard (100 %). |
| `heldout` | 8 | Never used to write or tune a rule. Measured only by `make eval`, gated on no regression against the baseline. |
| `heldout-2` | 16 | AI1's held-out split: written from the frozen contract in predeclared categories and pre-registered before any prompt or model exists. Never used to write or tune a prompt, a model configuration or a rule. Gated on no regression against its baseline; AI1's success thresholds are in its pre-registration. |
| `heldout-3` | 24 | assisted-2's held-out split, pre-registered (`eval/heldout-3-preregistration.md`) before assisted-2 was frozen and never used to tune it. Gated on no regression against `eval/heldout-3-baseline.json`. |
| `assist-dev` | 10 | Disjoint templates used to develop assisted-2; not a held-out split (integrity gates only). |

The held-out expected outputs were written from the contract alone before any extractor code existed. The extractor was then built from the contract and the dev cases only, frozen, and measured on the held-out split once. The resulting numbers are the baseline, including the misses. The extractor and its unit tests contain no held-out case (a test checks this).

**Limitation:** the same author wrote the held-out documents and the extractor, so the held-out split measures generalisation to *unseen phrasings*, not independence from its author. Held-out phrasings found missing may be added only as new dev cases in a separately reviewed change, and a fresh held-out set would then be needed to measure again without bias.

Changing any expected output or a baseline is a deliberate, reviewed diff: `make eval` never writes them, and `make eval-baseline SPLIT=<split>` rewrites only that split's baseline, and only when every hard gate passes. heldout-2's expected outputs cannot change at all without breaking its pre-registration test.

Baseline and assisted results per split: [`docs/evaluation.md`](../docs/evaluation.md).
